## P1 — real defects, closable by anyone with this repo

3. **Decision-Support recommends exactly one intervention.** Verified: 100% of its 6,108 recommended cells get `trees`. `cool_roof` is legal on every cell `trees` is legal on but loses on cooling-per-rupee by ~4.8× every time (0.8/5,000 = 1.6e-4 vs 1.0/30,000 = 3.3e-5), so it never wins. Worse: `cool_roof`'s intended exclusive land-cover class, `building_dense`, is a category the NDVI/LST proxy classifier can *never* produce — it only ever emits `vegetated`, `moderate`, or `bare_or_built_hot`. So `cool_roof` is not just losing a competition, it is mathematically unreachable right now, and nobody had called that out as distinct from the two *intentionally* disabled interventions (`pocket_park`, `green_roof`). Either accept "one intervention type" as the honest current behaviour and say so in the module README, or add a rule that reserves a minimum share of the budget for the runner-up intervention on each cell.
4. **`NEVER_TOUCH` excludes zero cells in practice.** The road/water/highway exclusion in `member3_decision_support.py` is real code, but the proxy land-cover classifier can never emit `road`, `highway`, `water`, or `wetland` — it only has three possible outputs, none of which are those four. The safety rule is currently dead code. Fixed by item 2's land-cover flip, but worth flagging now so nobody assumes the exclusion is protecting anything today.
5. **The QGIS project cannot be opened without three broken layers.** `Remote Sensing & Data Engineering/QGIS/guwahati_heat_project.qgz` references `./guwahati_boundary.geojson` (resolves inside `QGIS/`, where nothing lives — the file is in `Boundary/`), a `.shp` that does not exist anywhere in the repository, and an absolute path into a local `Downloads/` folder that only ever existed on the original author's machine. Fix: open the project, relink the boundary layer to `../Boundary/guwahati_boundary.geojson`, delete the two unresolvable layers, re-save, re-commit the `.qgz`.
6. **The model regression's headline number is misleading on its own.** `metrics.md` reports R² = 0.938 for the canonical model, achieved under a random 80/20 split on spatially autocorrelated data — neighbouring 100 m cells are nearly identical, so a random split leaks most test answers through their neighbours. The same model under a spatial-block split scores **R² = −0.02**, worse than predicting the mean. Both numbers are already committed; the improvement is presentational, not computational — quote the spatial-block number, or both, in any report or pitch. Never the 0.938 alone.

## P2 — worth doing, no urgency

7. **Frontend legend and colour scale should be revisited once real LST changes** (see item 2). Not broken today — the 24/27/30 breakpoints were retuned this session against the current real distribution (487/3,154/4,405/98 cells across the four bands) — but they are tuned to a temperature range that a corrected NDVI re-run could shift.
8. **`docs/04` through `docs/07` should be reviewed for cross-references once written.** [Status tracked in `docs/README.md`.] As pages land, check they cite the current section numbers in `urban_heat_analysis.js` (which grew from 12 to 17 sections this session) and the current property list in `grid.geojson` (which grew from six keys to seven with the addition of `cooling_c`).
9. **The `cooling_c` values are borrowed placeholders, not measurements**, and should eventually be replaced with something fitted to Guwahati — a simple regression against tree canopy fraction and albedo per cell would already be better than the current flat per-action constants (0.8 / 1.0 / 2.0 °C). Not urgent because the current values are honestly labelled as assumptions everywhere they appear, but "everywhere they appear" is a real integration surface (`tier_and_recommend.py`, `export_grid_geojson.py`, `compareView.js`) that a future fix must touch consistently.
10. **`Decision-Support`'s flat cost model should either be retired or explicitly rebadged** as an internal ranking weight rather than a cost estimate, now that the ML module's area-based model is the project's authoritative cost figure. Currently both files still print their numbers as if they were "the" cost; only this document and code comments make clear which one to trust. A one-line change to each module's terminal output (e.g. `cost_rupees (ranking weight only, see ML module for real estimate)`) would close that gap cheaply.
11. **No automated test suite anywhere in the repo.** The only integration check that exists is `export_grid_geojson.py`'s `validate()` function, which is good but narrow — it catches a schema mismatch, not a logic regression. A small pytest suite covering `tier_and_recommend.py`'s action table, the cost/cooling lookups, and `member3_decision_support.py`'s suitability rules would have caught the `"None"`→`"nan"` defect (item 12) automatically instead of by manual inspection.

## Fixed this session — kept for the record

12. **`recommended_action: "None"` was silently exported as the string `"nan"`.** pandas' default `na_values` list includes the bare string `"None"`, so `tiered.csv`'s 2,036 genuinely-no-action cells were read back as `NaN` by `export_grid_geojson.py` and then rendered as `"nan"` by `str()`. Not cosmetic: `compareView.js` tests `action !== 'None'`, and `"nan"` passes that test — every one of those 2,036 cells was having a cooling subtraction applied on the "After Intervention" map despite being explicitly marked as needing none, and every popup for those cells read "Suggested: nan". Fixed by scoping `keep_default_na=False` to the three string columns in `export_grid_geojson.py`, and closed against recurrence with a `VALID_ACTIONS` check inside `validate()`. This defect was not caught by the original integration audit; it was found verifying the pipeline re-run during this session.
13. **Three JS functions were each defined twice** (`colorByTemperature` in `mapView.js`, `buildPopupContent` in `popup.js`, `applyIntervention` in `compareView.js`) — merge residue from two earlier pull requests overlapping. JavaScript silently keeps the later definition, so the first was dead code misleading any future reader. Removed; the defensive (already-executing) definitions were kept.
14. **`Decision-Support/member3_decision_support.py` could not be run from a clean clone** — its input path was `/mnt/user-data/uploads/Guwahati_Urban_Heat_Dataset.csv`, a sandbox path that exists nowhere in this repository or on any machine that clones it. Fixed to resolve relative to `__file__`, matching the convention already established in `preprocess.py`. Verified: regenerates all three output CSVs byte-identical to what was previously committed.
15. **The dashboard had never displayed real data.** `frontend/js/main.js` loaded `mock_data/grid.geojson` — 900 synthetic cells spanning a fabricated 28–42 °C — despite the real 8,144-cell, 20.9–33.1 °C dataset having existed for a week. Switched to the real file, in its own commit, per the ML module's stated "no silent frontend data swap" guardrail.
16. **The frontend colour scale and legend were tuned for the wrong data.** `TEMP_COLOR_SCALE` bucketed at 30/34/38 °C — chosen for the mock data's range — against a real range of 20.9–33.1 °C, collapsing 98.6% of real cells into the coolest band. Retuned to 24/27/30 °C. The legend's labels were a second hardcoded literal that could silently disagree with the scale; labels are now derived from the scale so the two cannot desync.
17. **No `LICENSE` file existed.** Added MIT for the source, with a data-attribution section for geoBoundaries, Landsat, ESA WorldCover and OpenStreetMap, which carry their own terms.
18. **No cross-module integration audit was in the repository.** It existed only as a local file. Committed to the repo root; findings verified against source before committing, not taken on trust.
