# Urban Heat Island Dashboard — Frontend

Interactive split-screen map comparing current heat conditions vs. projected
temperatures after cooling interventions (trees, cool roofs, green parks).

A deeper walkthrough of every file lives in [`../docs/06-frontend.md`](../docs/06-frontend.md).

## Running locally

```bash
cd frontend
python3 -m http.server 8000
```

Open `http://localhost:8000/` in a browser.

You must serve over HTTP. Opening `index.html` as a `file://` URL fails — the
dashboard loads its data with `fetch()`, which browsers block for local files.

## Data

The dashboard reads a single file: **`data/grid.geojson`** — the real pipeline
output, 8,144 Guwahati cells, produced by
`Machine Learning & Prediction/scripts/export_grid_geojson.py` and copied here.

`mock_data/grid.geojson` (900 synthetic cells, generated by
`mock_data/generate_mock.py`) is kept for offline development. Point
`js/main.js` at it if you want to work without the real data.

## Data contract

Each GeoJSON feature must have these properties. `export_grid_geojson.py`
enforces this exact key set in its `validate()` function and refuses to write
a file that does not match — so if the dashboard renders, the contract held.

| Field                | Type    | Example      | Notes                                              |
|----------------------|---------|--------------|----------------------------------------------------|
| `grid_id`            | string  | `"+102027+29089"` | Unique ID per cell (join key)                 |
| `temperature`        | number  | `27.7`       | °C. Real range 20.9–33.1. Missing renders grey/"N/A" |
| `ndvi`               | number  | `0.246`      | Vegetation index. **Uncorrected — see below**      |
| `priority`           | string  | `"High"` / `"Medium"` / `"Low"` | Drives the filter buttons       |
| `recommended_action` | string  | `"Tree cover"` / `"Cool roof"` / `"Green park"` / `"None"` | Shown in popup; gates the intervention shift |
| `cost_estimate`      | number  | `334350`     | ₹ INR, integer — popup calls `.toLocaleString()`   |
| `cooling_c`          | number  | `0.8`        | °C this cell's intervention is assumed to remove   |

Every field is handled defensively — a missing or malformed value renders as
"N/A" or grey rather than throwing — but the dashboard is only meaningful once
real values are present.

**Geometry:** one Polygon per feature, a single grid cell. Real cells are
0.00089832° squares in EPSG:4326 — about 89.8 m × 99.3 m at this latitude, not
exactly 100 m × 100 m.

## How the "After Intervention" map works

`js/compareView.js` deep-copies the loaded GeoJSON and subtracts each cell's
own `cooling_c` from its `temperature`, but only where `recommended_action` is
present and not `"None"`.

If a feature carries no `cooling_c` — which is the case for every feature in
the legacy `mock_data/grid.geojson` — it falls back to a flat 3 °C, the
behaviour the dashboard had before per-cell cooling existed. A `cooling_c` of
`0` is respected as a real zero, not treated as missing.

**The cooling values are assumptions, not predictions.** They originate as
placeholder engineering estimates (0.8 / 1.0 / 2.0 °C by intervention type).
The right-hand map illustrates a policy; it does not forecast an outcome.

## Colour scale

`js/mapView.js` buckets temperature at **24 / 27 / 30 °C**, tuned for the real
Guwahati distribution (20.9–33.1 °C, median 27.3, p99 30.2). The legend labels
are derived from `TEMP_COLOR_SCALE` rather than hardcoded, so the two cannot
drift apart.

If you regenerate the data after the upstream NDVI fix lands, re-check these
breakpoints against the new distribution.

## Features

- Split-screen before/after comparison with synced pan and zoom
- Click any cell for temperature, NDVI, priority, recommendation and cost
- Filter by priority (All / High / Medium / Low)
- Location search (geocoder, top-left of the left map)
- Loading state and graceful handling of missing or malformed data

## Pointing the dashboard at different data

1. Regenerate: `python scripts/export_grid_geojson.py` in the ML module.
2. Copy `Machine Learning & Prediction/Results/grid.geojson` to
   `frontend/data/grid.geojson`.
3. Hard-refresh the browser. No code change is needed if the property names
   match the contract above.

The copy is deliberate rather than a relative `fetch()` across module
directories — the ML module's path contains a space and an ampersand, which is
fragile to URL-encode from the browser. It also means **regenerating the file
does not update the dashboard until you copy it across.**

## Known limitations

- `ndvi` values shown in popups are uncorrected and compressed low (max 0.386
  across the whole city, where 0.7–0.85 would be expected). The fix is
  committed in the Earth Engine script but the data has not been regenerated.
  See [`../docs/08-limitations.md`](../docs/08-limitations.md).
- `cost_estimate` figures are order-of-magnitude planning placeholders, not
  procured or tendered costs.
- Coverage is the geoBoundaries ADM3 "Guwahati" polygon (~81 km²), which is
  smaller than the full municipal extent.

## File structure

```
frontend/
├── index.html          script load order matters — plain globals, no modules
├── style.css
├── data/
│   └── grid.geojson    real pipeline output, 8,144 cells
├── mock_data/
│   ├── generate_mock.py
│   └── grid.geojson    900 synthetic cells, offline development only
└── js/
    ├── dataLoader.js   fetch + JSON parse
    ├── mapView.js      Leaflet init, colour scale, layer + legend rendering
    ├── popup.js        per-cell popup markup
    ├── compareView.js  the two maps, their sync, the intervention transform
    ├── filters.js      priority filter buttons
    └── main.js         entry point — load, render, hide the loading screen
```
